## 4. 风险与分歧点

1. **状态口径分歧**：`G06-01-ledger-append-only-ddl.yaml:13` 标 `executed-pending-live-evidence`，但其唯一剩余请求是 PG 迁移编号（`REQ-G00-ledger-trigger-migration-number`，:33-39），更像 `executed-pending-pg-migration`；`G06-01.yaml:5` 的剩余是 G02-01/G00-04。是否纠正见 §6。
2. **陈旧注释**：`G06-02-provider-callback.yaml:3-5` 仍写 `PAYMENT-CALLBACK-REPLAY` 是「当前唯一 `blocks_release=true` 的缺口」，与 :15-19 及 `known-gaps.json:70/146` 冲突；status 字段本身正确。
3. **PG DDL 幂等性**：提案用 `CREATE OR REPLACE FUNCTION` + `DROP TRIGGER IF EXISTS`（:66-75 等），重跑安全但不是纯 `IF NOT EXISTS` 风格；`ledger_closing_balances` 复用 `ledger_closings_immutable()`（:159-162），报错文案会串。落 M010 前需确认 registry 的 idempotency 口径。
4. **发布门槛双轨**：`known-gaps.json:31` 的 `G00-04-PG` `blocks_release=false`，但 `integration-requests/G16/G16-05.yaml:7-11` 的 `G16-05-PG` `blocking=true`。闭环判据须以 G00-04 close_when + G16-05 证据对齐，避免「台账说 open、发布说 blocking」的认知差。
5. **live evidence 涉及真实资金**：必须 sandbox 先行；幂等键与 `operation_id` 已就绪，仍需授权与回滚预案。
6. **本车边界**：`ci/**`、`crates/**`、`server/**`、`deploy/**`、`containers/**` 均属他车/禁改，本报告不动；S1–S6 由主代理派工。
