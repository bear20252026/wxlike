# G00-04 S3 — M019-M022 消息/关系/序列号 PG 覆盖

状态：M019-M022 已登记并进入 `pg-migration`；SQLite 快照的 110 张表/视图都有
PG `CREATE TABLE`/`CREATE VIEW` 对应对象，`crates/platform/tests/pg_schema_parity.rs`
把这条覆盖关系钉成回归测试。

## 1. 为什么补这四步

M014 的平台兼容层覆盖了旧平台表和 11 张 identity 兼容表，但 `crates/message`
的 G03 信箱/投递表、`crates/features/relations` 的 ACL 表、identity 的全局令牌
序列号一直没有 PG 落点。对照 `schema_snapshot.txt` 与
`schema/proposals/**/*.sql`，当时缺 20 张物理表；本组迁移逐列补齐，全部
`expand-only`，不改 SQLite 行为。

`users` / `sessions` / `media` 不在这 20 张里：它们是 M011/M012 的同名兼容视图，
parity 测试同样识别 `CREATE OR REPLACE VIEW`。

## 2. 四步迁移

| 编号 | 文件 | 表 |
| --- | --- | --- |
| M019 | `schema/proposals/G03/0001_message_timeline.sql` | `owner_seq`、`mailbox`、`read_cursor`、`msg_user_state`、`mailbox_change`、`ephemeral`、`member_log`、`member_snapshot` |
| M020 | `schema/proposals/G03/0002_message_delivery.sql` | `message_submit`、`delivery_task`、`device_cursor`、`conversation_projection`、`conversation_pref`、`conversation_clear`、`conversation_event`、`push_device` |
| M021 | `schema/proposals/G02/0007_relations_acs.sql` | `friend_acs`、`friend_policy`、`group_member_acs` |
| M022 | `schema/proposals/G02/0008_identity_token_serial.sql` | `identity_token_serial` |

类型映射只有两条：SQLite `TEXT` 保留 `TEXT`，`INTEGER` 统一 `BIGINT`。
`ephemeral.rowid_hint` 与 `conversation_event.id` 的 `AUTOINCREMENT` 改成
`BIGINT GENERATED BY DEFAULT AS IDENTITY`；`identity_token_serial.id = 1`
的 `CHECK` 原样保留。索引名与 SQLite 一致，避免两套命名。

## 3. CI 证据

`pg-migration` 作业在 PostgreSQL 16 上：

1. 把 M019-M022 四个文件各跑两遍，验证 `IF NOT EXISTS` 可重入；
2. `pg_migration_asserts_g03.sql` 检查 20 张表、131 列、8 个索引，列类型必须是
   `text` / `bigint`；
3. `pg_m019_m022_behavior.sql` 写最小 fixture，验证默认值、生成列、复合主键、
   `mailbox.msg_id` 唯一索引、`message_submit.msg_id` 唯一约束、
   `identity_token_serial` 的 `id=1` CHECK，最后清理；
4. 备份/恢复演练恢复到新库后重跑同一份 M019-M022 形状断言，确认表、索引随
   `pg_dump` 完整回来。

## 4. 本地守卫

`crates/platform/tests/pg_schema_parity.rs` 读取提交的 SQLite 快照，扫描
`schema/proposals/**/*.sql`，要求每个 SQLite 表/视图都能找到 PG 对象。它不替代
PG 实跑，但能在本地第一时间抓住“新表只加 SQLite、忘了写 PG 迁移”。解析器还
有一个小测试覆盖 `CREATE TABLE IF NOT EXISTS`、`CREATE OR REPLACE VIEW`、
`CREATE UNLOGGED TABLE` 三种写法。

```powershell
cargo test -p wxlike-platform --test pg_schema_parity
cargo test -p wxlike-media --test migration_registry
```

## 5. 回滚

- M019：`DROP TABLE owner_seq, mailbox, read_cursor, msg_user_state, mailbox_change, ephemeral, member_log, member_snapshot;`
- M020：`DROP TABLE message_submit, delivery_task, device_cursor, conversation_projection, conversation_pref, conversation_clear, conversation_event, push_device;`
- M021：`DROP TABLE friend_acs, friend_policy, group_member_acs;`
- M022：`DROP TABLE identity_token_serial;`

全部是新增对象，回滚不触碰 M011/M014 的兼容视图与既有平台表。M022 回滚后
下一次全局令牌轮换会从 0 重新起算，已签发令牌的失效语义不变。
