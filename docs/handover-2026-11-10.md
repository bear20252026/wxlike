## 3. main 的门禁现状（最容易误读的部分）

现查 `50b217f` 的 check-run：

- `gate` = **success**（分支保护只要求 `gate` 这一个 context，`strict=true`）。
- `audit` = **skipped** ← 关键：那次 push 只改台账，`select` 按路径把它跳过了。
  而 ci 的 `audit` 作业里就跑着 `cargo deny check advisories` 和 `cargo audit`。
- `security (online advisories)` / `security (source + policy)` / `security (gate)` = success。
- **`cargo audit (RustSec)` = failure**（`audit.yml` 的作业，**不在必过清单**，红着也不拦合并）。

⇒ 三条推论，接手时直接照用：

1. "main 全绿" ≠ "公告检查过了"。要证明某个作业真的过了，去数那个 commit 上有没有对应 check-run。
2. **碰 `Cargo.lock` 的 PR 现在一律合不进去**（会真跑 `audit` → deny 报 0459 红 → `gate` 红）。
   只碰台账/文档的 PR 会被 skip，照常能合。#375 是前者的活样本。
3. 我说"某作业已修好"时必须附**是哪一次 run**（push / dispatch / schedule）以什么结论过的。
   例：#377 并入后 push run 显示 `skipped`，我用 `gh workflow run security.yml --ref main`
   打了 dispatch run `42762614853`，四个作业才拿到 success——那才是证据。

## 7. 我这轮犯过、并已写进台账的错（供接手人少走一遍）

1. **拿 `tail` 窗口当全集**：从 CI 日志的一屏里数出"typos 5 处"并贴到 PR 上，全量是 16 处。
   正确做法：`gh api …/jobs/<id>/logs | grep -oE "error: \`[a-zA-Z]+\`" | sort | uniq -c`。
   更正必须是公开的一条，不能悄悄改数字。
2. **`git checkout --` 抹掉自己未提交的改动**：为归一 LF 而 checkout 两个正带新编辑的文件，
   编辑当场消失。**要读规范化字节就 `git add` 后 `git cat-file -p :<path>`，不碰工作树。**
3. **先动无主路径、再问归属**：把共享词汇表塞进 `crates/core/src/types.rs`，
   越界（G02 只有 `crates/core/src/e2ee.rs`）。已 `revert` 再补 IR，改动留成可 cherry-pick 的提交。
4. **凭近似名推断范围**：先说"三车道的公开 API"（其实三个 crate 同属 G02），
   又说"不用跨组"（其实 `crates/platform` 才是拦路的）。判范围只看 `teams/*.md:5` 的路径列表。
5. **抬 lock 忘了重生成 SBOM**：CI 直接报 `SBOM-DRIFT-ADD/REMOVE`，fail=2。是我的漏项，不是误报。
6. **把"没跑"读成"过了"**：#377 并入后 push run 里那个作业是 `skipped`；靠 dispatch 才算证实。
7. **`grep -c $'\r'` 判换行符在这条 bash 链路上结果相反**（对 LF 文件返回总行数）。
   用 `tr -dc '\r' < f | wc -c`；比对 blob 用 `git cat-file -p`，**不要用 `git show`**（它套 checkout 转换）。
8. **给并行 worktree 各开一份 `target/` 把 D: 写到 0 G**（`os error 112`）。
   回收只碰自己造的：`target/debug/incremental`（约 2.5 G，纯可再生）与自己那几个 worktree；
   共享 `target/debug/deps`（约 18 G）**不要动**。
9. `sourceaudit all` 不接受 `--timeout`（只有 `advisories` 子命令接受），rc=2 是用法错误不是门禁红。
