# wxlike vs 微信 / Telegram / 成熟 IM 功能对照表

> 2026-10-16。逐域核对代码后的实证版（每行的 wxlike 状态都有测试/代码证据支撑）。
> 图例：✅ 已实现且有验证 · ⚠️ 部分（库就绪/未接入/未真机）· ❌ 未实现 · ➖ 任务书范围外。
> 参考基准：微信（消费级全功能）、Telegram（全球化+强协议）、HuLa/唐僧叨叨/box-im（开源同类）。
> 范围声明：本项目按 docs/WORK_BREAKDOWN.md 的 14 个工作包交付，**任务书不含移动端**。

| 域 | 微信 | Telegram | wxlike |
|---|---|---|---|

## 差距汇总（按补齐收益排序）

1. **E2EE 接入客户端消息路径**（库已完备，差接线+回退日志）——这是"安全 IM"的成色问题，建议最先做；
2. **手机端**（任务书无此 WP）：Rust core 已是 TDLib 形态，走 UniFFI/cargo-ndk，UI 原生或 Tauri mobile（HuLa 路线）；
3. **消息操作五件套**：转发/合并转发/收藏/正在输入/搜索（唐僧叨叨 Apache-2.0 可直接对照搬模型）；
4. **UI 产品化**：历史消息加载、消息列表虚拟化、语音条/文件消息、置顶、多语言（HuLa 组件可借）；
5. **通话接 UI + 真机双机验收**（rtc 库已就绪，差 UI 集成和真机过场）;
6. **发布工程**：安装包/bundle、release CI、HTTP 反代 TLS、TURN/FCM 部署文档；
7. **服务端成长路线**（PG + 分片 + 风控），sandcat-backend 的微服务拆分可对照。
