# wxlike 威胁模型（WP-12 A3）

> 一页纸版本。回答两个问题：这套加密**保护什么**、**不保护什么**。写明的边界就是边界，
> 没写的请当"不保护"处理。

## 参与者与信任假设

| 角色 | 信任程度 |
|------|----------|
| 发送者/接收者（双方设备） | 完全信任。密钥只存在这里。 |
| hub / server 运营者 | **零信任**（诚实但好奇乃至恶意）：能看、能改、能重放一切经过它的字节。 |
| 网络（QUIC 之下） | 零信任。 |
| platform（SQLite 数据面） | 与 hub 同级：零信任，只当目录和存储用。 |

## 保护什么（E2EE 范围）

1. **单聊消息体**（`MsgBody`）— Olm 双棘轮（X3DH 建立会话 + 双向 DH 棘轮），
   基于 `vodozemac`（Matrix 同款实现，Apache-2.0）。
   - 前向保密：每条消息独立密钥；设备被攻破不回溯历史。
   - 后向保密（会话内）：棘轮推进，旧消息密钥销毁。
   - 篡改检测：AEAD，任一比特改动解密必败。
   - 重放拒绝：己方维护已解密密文集（Olm）与消息索引水位（Megolm）——
     vodozemac 明确把重放防护留给嵌入方，我们补上了。
   - 乱序容忍：128 条重排窗口（vodozemac 原生 40 条，接收端严格有序缓冲扩到 128）。
2. **群聊消息体** — Megolm sender-key（每说话者一把出站密钥，1:1 通道分发）。
   N 人群不做 O(N²) 两两协商；成员变更触发轮换，新成员读不到轮换前的历史。
3. **传输层身份** — QUIC 证书 TOFU 钉扎（首连记指纹，之后证书变了就拒绝），
   替换默认的 skip-verify；`--insecure-lab` 显式开关才允许跳过。
4. **推送内容** — 离线推送 payload 只含"谁发了消息"，不含正文。

## 不保护什么（明确边界）

1. **元数据不隐藏。** hub 必须路由，因此以下全程明文可见：
   `Envelope` 的 `conv_id`、`sender`、`to`、`sent_at_ms`、`msg_id`、消息大小、收发时机、
   谁和谁在什么时候通信（流量分析）。这是路由型 hub 架构的固有权衡，不是疏漏。
2. **platform 数据面内容** — 资料昵称签名、好友关系、群成员表、朋友圈可见性判断、
   虚拟钱包账本都在服务端明文（业务上必须）。服务器被攻破 = 这些泄露。
3. **TOFU 首连窗口** — 第一次连接若已被中间人截持，钉住的就是攻击者证书。
   缓解：关键场景可在带外核对 `identity_signing`（Ed25519 指纹/安全码）。
4. **被攻破的设备本身** — 恶意客户端可以转发明文。E2EE 不防端点。
5. **服务端拒绝服务** — hub 可以丢弃一切。加密不解决可用性。
6. **媒体文件的缓存** — 媒体经 `/api/media` 上传下载是 TLS/TOFU 保护，不是 E2EE；
   媒体引用 id 出现在消息体内随 E2EE 保护，但对象存储在服务端。

## 密钥生命周期

- `Device`：Olm 账户（Curve25519 身份密钥 + Ed25519 签名密钥 + 一次性预密钥批次）。
- 预密钥目录：`POST/GET /api/keys`（platform）。**GET 是认领语义**——每次弹出一把
  一次性密钥，绝不重复发放；库存见底返回空列表，属主端 `bundle_refilled` 补货。
- 群 sender key 分发走成员间 1:1 加密通道，不经过服务端。

## 兼容与迁移

- `wxlike-core::crypto` 的 static-static 脚手架（X25519+HKDF+ChaCha20-Poly1305，
  无棘轮/无前向保密、AAD 不含会话上下文、全仓零调用者）已移除（issue #47）。
  客户端封消息的唯一路径是 `e2ee.rs` 的 Olm/Megolm。
- 本地快照：旧 `WXSC1`（裸设备密钥同目录存放）→ 新 `WXSC2`（口令 → Argon2id →
  XChaCha20-Poly1305，盐与 KDF 参数随密文头存储）。旧文件**明确报错拒绝**，不做
  静默迁移；桌面端接入口令解锁见整改任务单 T-D3（issue #48）。
