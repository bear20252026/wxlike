# 可审查脚本示例

这三个脚本是**给人审的**，不是产品代码：只用只读命令或 `--dry-run`，
任何一步都不会改数据。审计时按顺序读一遍就能判断"这个 AI 到底能干什么"。

前置条件只有两个环境变量：

```sh
export WXLIKE_SERVER=http://127.0.0.1:8099
export WXLIKE_TOKEN=<登录后的会话令牌>
# 只读审计用的白名单（示例：一个群 + 一个直聊）
export WXLIKE_AGENT_ALLOW_CONV='g-demo-1,d-bob~alice'
```

| 脚本 | 作用 | 是否写数据 |
|---|---|---|
| `audit-read-only.sh` | 拉一遍只读快照：我是谁、有哪些会话、未读多少、最近历史 | 否 |
| `export-plan.sh` | 生成"要导出哪些消息"的计划（含参数摘要），供人复核 | 否 |
| `gate-check.sh` | 体检：`doctor` + `coverage` + 权限判定，坏配置直接退出非 0 | 否 |

为什么示例脚本值得单独放：**AI 命令面的风险不在"能不能调"，而在
"调了之后没人看得懂"**。这三个脚本把"能做什么"变成可 diff 的文本输出，
审计员不需要读 Rust 也能签字。

约定：

* 全部输出 JSON（`--json`），一行一条，便于 `jq`/`diff`；
* 全部只用 `Capability::Read` 的命令，或显式 `--dry-run`；
* 不写临时凭据文件、不打印令牌（令牌只从环境变量读，且 `doctor` 只报"是否配置"）。
